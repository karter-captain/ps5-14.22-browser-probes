Notes for 14.22 testing

What this suite is

Purely diagnostic pages. They do not contain any exploit chains. They exist so you can observe how the 14.22 browser behaves under common allocation patterns, feature checks, and edge cases that historically mattered for WebKit entry points.

What to watch for

  • Unexpected browser freezes or black screens
  • Kernel panics (console restarts)
  • Differences in maximum ArrayBuffer size vs earlier firmwares
  • Missing or changed WebAssembly / SharedArrayBuffer behavior
  • Any contentDocument or postMessage differences inside sandboxed iframes

Logging tips

  • Keep a phone or second device filming the TV if the console locks up
  • Note exact timing of any crash relative to which button / allocation size you pressed
  • If you get a reproducible panic, write down the last successful log line

Responsible path

If you discover something that looks like a real memory-corruption or sandbox-escape primitive, the current scene norm is to report it through Sony’s HackerOne program first. Public release usually follows after the fix is shipped.

Disc drive note

You have a disc drive, so BD-J remains a theoretical secondary surface. These browser pages will not exercise BD-J. That path needs different tooling (disc image + Java classpath tests).
